# History, file history and blame

The History view, its rows, refs, people and search, and the File history view with Blame. The graph's data model is in [ARCHITECTURE.md](ARCHITECTURE.md) §3.9.

## History view

- The graph list (graph, ref chips, subject and an outgoing upload icon) on the left; on the right, the selected commit's details (`CommitHeader`) above its file list, which sits beside the diff of the selected file.
- **Scope:** Current branch (all ancestors of HEAD, including merged history) is the initial scope; All branches includes other refs. The filter's options popover offers Branches `Current | All` (remembered per worktree, never checking out a branch), Rows `Compact | Detailed` and Show graph. The scope is not counted on the options button; it is in its tooltip. Each scope rebuilds the graph and reruns the search within it.
- There is no row between the search field and the list: no commit count, scope or tracking row; while searching the field itself counts the matches ("3/41", "No matches"). A failed load shows its error over the list.
- **Outgoing** means reachable from HEAD but not its configured upstream, using local refs; without an upstream (or with a gone one), commits on no remote branch (`rev-list HEAD --not --remotes`). Outgoing rows show the push icon (its tooltip names the upstream, or "Not on any remote") and the Sync button counts them.
- **Go to current commit** is keyboard-only (`F` by default): it selects the checked-out tip without clearing search and does not intercept typing in text fields.
- Reloads follow HEAD when it was selected, otherwise keep the selected hash if it remains in scope and fall back to HEAD when it does not.
- A merge's parents are keyboard-accessible links ("Merges 8ecc768 → e098728": the parents brought in, then the one merged into) that select and reveal the parent in the graph without clearing search; requests wait during progressive loading, while unavailable parents leave the selection unchanged and say why.
- Ctrl+click a second commit selects two rows → **Compare commits** ([COMPARE.md](COMPARE.md)).
- `HistoryView.reveal_commit(oid, in_head)` selects a commit once it is listed and, when the current scope lacks it, lists all branches first (used by File history's Open in History).

## Rows

- **Detailed rows** (the default): two lines, 50 px: the subject on top; below it the author's avatar with the co-authors' stacked after it, "Author +N" and the date, and the refs on the far right of that line. A faint divider under each row, starting where the text starts so the graph stays unbroken, ties each author line to its subject (none beside the selection). A commit to push has the push icon at the top right. Row heights can be compared with `history_rows_screenshots.tscn --row-heights=…`.
- **Compact rows** (`history_compact`; View → History ▸ and the options popover, actions `history.compact_rows` / `history.detailed_rows`, `history.toggle_compact` flips): one 24 px line with the subject first and, on the right, one icon-only chip per kind of ref (the first ref's colour and icon, with the count when there are several; a click lists them all, a right-click on one ref is its menu) and then the author's avatar; a commit to push has the push icon before its subject.
- **Show graph** (`history_graph`, on by default) off leaves the graph out, the text starting at the left edge.
- **Dates** (`RelativeDate`): relative up to 30 days ("3 h ago", "12 days ago"), then a short date this year ("Mar 4"), then `YYYY-MM-DD`; the exact time is in the tooltip.
- `CommitList` takes its rows from a source (`_fetch_rows`) and can leave the graph out; Compare's and File history's lists extend it (`_trailing_width`, `_draw_trailing` for marks after the ref chips). Only a window around the visible rows is fetched.

## Refs

- Tags and branches have distinct shapes and colours (`RefChip`, `godot/ui/ref_chip/`: branches square-cornered, tags a round pill with the tag icon), cut to 160 px with an ellipsis.
- Per commit, one branch chip (the current branch, else a local branch, else a remote-only one) and "+N" for the rest, then one tag and "+N". The "+N" chip opens a popover (`refs_popover.gd`) listing every ref of the commit, the merged remote branches muted beside their chip, each with the ref's menu; it opens under the chip on a click or right-click.
- A local branch whose remote-tracking branch is merged into it is one chip with a cloud icon in place of the branch icon (the tooltip names the remotes). A remote branch merges into a local one when it is that branch's upstream, or, for a branch without an upstream, when it has the same name on any remote. A remote branch not matched that way is its own chip, cloud icon and `origin/` prefix, in the muted remote colour. The current branch keeps the accent fill.

## People

- Author plus `Co-authored-by:` trailers (not `Signed-off-by`; `repo/trailers.rs`), parsed during the graph load and interned like authors; the history search matches co-authors too.
- The details show the author, each co-author and the committer when their name or email differs from the author's, as cards: a 30 px avatar beside the name (with "Co-author" or "Committer" muted after it) over the email; the committer's tooltip gives the commit date. The date sits on the hash row (tooltip "Author date"); every ref shows as wrapping chips beside the hash, and a click on one opens its menu.
- `CommitHeader` (summary, people, date, hash, refs, message) is shared by History, Compare and File history; `CommitDetails` adds the file list.

## Avatars

- Missing, loading, offline or turned off: initials on a colour chosen per email from a fixed palette that reads in both themes (`AvatarPainter`).
- Lookups per email, first hit wins: a GitHub noreply address (the user id gives the URL directly); on a github.com remote, the newest commit on that remote's branches the person authored, or else committed (`GitBackend::published_commit_by`), through GitHub's commit API (the user's own token from `GH_TOKEN`/`GITHUB_TOKEN` or `gh auth token` if available, otherwise unauthenticated; never git's credential helper, which may open a sign-in window); GitLab's public avatar API on the repository's GitLab hosts, then gitlab.com; Gravatar, then Libravatar, by the email's SHA-256 with `d=404`; GitHub's commit search by author email last (public commits anywhere; its tighter rate limit leaves it alone for a minute after a refusal).
- Requests carry only the email. A miss notes whether a GitHub remote was asked and is looked up again from a repository on GitHub when none was. Each session asks once per email.
- **Cache:** `<cache dir>/avatars`; pictures are named after their provider (`<key>.<provider>.<ext>`), refreshed after 30 days (shown meanwhile), misses retried after 7 days. A miss lists the providers it asked, so turning one on looks again.
- **Settings → Interface:** "Show profile pictures" (`avatars`; off draws initials only) and Picture sources (GitHub, GitLab, Gravatar, Libravatar; `avatar_providers`).
- Code: `gitbello_core::avatars` (`CurlRunner`, the sources, `AvatarCache`), `Runtime::request_avatar` (cache read, then up to three lookups at a time, background priority), `GITBELLO_AVATAR_ENDPOINT` puts every source under one URL (tests use a local stub or a closed port). In Godot, `AvatarPictures` cuts each picture to a round 64 px texture; History, Compare, File history, Blame and the details' cards ask through their session. `gitbello-cli avatar <email>` looks one up by hand.

## Search

Find and highlight, not a filter: hiding rows would break the graph's lanes.
- Core `CommitSearch` (`graph/search.rs`): case-insensitive substring of subject, author name or email, co-authors; 4+ hex characters also match hash prefixes. No git call: it runs as a job over the index in chunks under its read lock, follows rows as the graph loads, cancels on a new query and reruns on a graph reload. Results are sorted match rows plus progress.
- `RepoSession`: `search_commits(query)`, `search_info()` (`{query, matches, searched, done}`), `next_match(row, forward)` (wraps), `search_match_index(row)`, a `match` flag in `graph_rows`, `search_overview(buckets)` and the `search_changed` signal.
- The shared `FilterField` sits right above the list. When a search finishes, the first match from the selected commit down is selected; Enter / Shift+Enter, F3 / Shift+F3 and the ↑ ↓ buttons move between matches; Escape clears; Ctrl+F (`view.find`) focuses the current view's field. Non-matching rows are dimmed (subject and graph dot) and the query is highlighted in matching subjects. A `MarkStrip` beside the scroll bar shows where the matches are ([DIFF_VIEW.md](DIFF_VIEW.md#navigation)).

## File history

The commits that changed one file, each with its diff of that file. Files only.

```
( Changes 3 | History | File history × )
 src/login/auth.rs                                   [Blame]
+--------------------------------+----------------------------------+
| Uncommitted changes    +3 −1   | Improve login                    |
| Improve login                  | (C) Caleb · 3 h ago · 1a2b3c4    |
|  (C) Caleb · 3 h ago   +40 −12 | body…                            |
| Move auth into login/          +----------------------------------+
|  (A) Ann · Mar 4  [Renamed] +2 | src/login/auth.rs   +40 −12      |
| Add auth                       |  @@ -10,6 +10,9 @@               |
|  (A) Ann · Feb 20  [Added] +88 |  ...diff of this file only...    |
+--------------------------------+----------------------------------+
```

- **View:** joins the switch only while open, with a close × on its tab (`ClosableViewTab`, shared with Compare). One per worktree: opening another file replaces it; closing returns to the view it was opened from. Not restored on restart. It has its own diff slot (`DiffSlot::File`, the `file` slot id), so History and Compare keep their selection. Its tab and action have their own icon, `FileHistory`.
- **Bar:** the file's icon and path (`PathLabel`: folder muted, cut first when narrow; the tooltip lists other names the file had, "Also: src/auth.rs"), an "as of <branch, tag or subject>" chip when the history starts from a commit other than HEAD, and the Blame toggle.
- **Rows:** History's rows without the graph (`FileHistoryList`, a `CommitList`): on the right, the lines this commit added and removed in the file (`+40 −12`; nothing for a binary file) after a chip when the commit **Added**, **Renamed** (tooltip "Renamed from src/auth.rs") or **Deleted** the file. No ref chips; the details show them. Rows follow History's Compact/Detailed setting (the field's options popover has Rows).
- **Uncommitted changes:** a first one-line row while the history starts from HEAD and the file has local changes; it shows the working copy against HEAD, read-only, with its status chip and the lines added and removed (counted after every status refresh by `count file history changes`: `git diff --numstat -M <HEAD or the empty tree> -- [old name] <path>`). A file that is new and not committed yet shows this row alone. A rename not committed yet reads the history of the old name.
- **Filter:** History's field over the versions: subject, author, email, co-authors or hash (4 or more hex digits); it marks the text in the subjects, leaves the uncommitted row out and counts the matches ("2", "No matches"). It lives in core (`VersionFilter`), so rows, the selection and `file_history_index` follow it.
- **Right side:** the selected commit's details (`CommitHeader`) over the diff of the file in that commit against its first parent; no file list. The diff is read-only and keeps the diff modes, Show whole file, the minimap and the image viewer. A renaming commit's diff header reads old → new.
- **Start:** the history is read from the revision the file was seen at: HEAD from Changes, Shelves and Compare's working-copy side; the selected commit from History's file list; the side (or the narrowed commit) from Compare. So a file deleted or renamed since still has its history, under the name it had there.
- **Order and merges:** newest first. A merge shows only when the file after it differs from every parent (git's history simplification), with its diff against the first parent. `--diff-merges=first-parent` on `log` would turn the simplification off (on `git/git`, 21,072 commits for `Makefile` instead of 3,285), so the log asks for no merge diffs and `git diff-tree --stdin --diff-merges=first-parent` reads those merges, a batch per chunk of the log. The commits listed are exactly `git log -- <names>`'s.
- **Renames:** `git log --follow` is not used: it tracks one name at a time while it walks, so it loses commits made under the old name on a branch merged after the rename. Instead the log is limited to every name the file is known to have had (`git log -M -- <new> <old>`): the first pass takes the given name; when it reaches the commit that added a name, the tree diff of that commit with rename detection (`GitBackend::rename_source`) says whether it was a rename, and if so the old name joins the set and one more pass runs with both. Passes stop when no new name turns up, at most 8 names (`MAX_NAMES`). A later pass lists a superset of the earlier one in the same order, so the list only gains rows and the selection is kept by commit. Copies are not followed.
- **Entry points:** **File history** (`file_history.open`, Ctrl+Shift+H) on the file that has the focus: the highlighted file of Changes, History's commit files, Compare's files and a shelf's files, or the file of the diff shown; in each of those lists' menus, the diff's menu and the palette. Disabled with the reason for a submodule or an ignored file's row. File history on a file whose history is already open leaves Blame as it is. `file_history.close` closes it.
- **A version's menu:** **Compare versions** with two rows selected (Compare with the older version left and the newer right as a full difference, its filter set to the file's exact path in double quotes); **Restore version** (`file_history.restore`: the file as it was at that commit, written under the name the file has now, backed up first, the toast offers Undo; written from `cat-file --filters --path=<dest>` so line endings and filters follow the destination; disabled for a deleting commit and for Uncommitted changes); **Open version** (the default app, through Open's versions cache); **Open in History** (`file_history.show_in_history`); Copy ▸ hash.
- **Refresh:** a history that starts from HEAD reloads behind the rows when HEAD moves (swapped in when it ends), keeping the selected commit when it is still listed; its Uncommitted changes row follows the status. A history from a fixed commit never reloads.
- **Core:** `path_log` (the pathspec-limited log: `git log <start> -z -M --raw --numstat --format=<the graph's fields> -- <paths>`, streamed into `PathCommit`; records are cut at NUL + `\x1e`; `PathLogSplitter`), `file_history` (`FileHistoryLoader`, `FileVersion`, `WorkingVersion`), `runtime/file_history.rs` (`FileHistoryState`, read job `file history` at normal priority that supersedes the same worktree's older one and is cancelled on close, rows published in batches; job `load file history commit` for the details; `RuntimeEvent::FileHistoryChanged`). `path_log` is also what a folder's history or a search by path would build on.
- **gdext:** `open_file_history(path, start, start_name)`, `close_file_history()`, `file_history_info()` (`{path, names, start_name, count, total, filter, loading, error, has_working, working, selected}`), `file_history_rows(start, count)` (commit rows plus `path`, `original_path`, `change`, `added`, `removed`, `working`, `exists`), `file_history_index(oid)`, `select_file_version(oid, full)` (empty `oid` for Uncommitted changes), `set_file_history_filter`, `file_version_details()`, `clear_file_diff()`, `restore_file_version(oid)`; signals `file_history_changed` and `file_history_diff_changed`.
- `gitbello-cli file-history <root> <file> [--from <rev>] [--rows a..b] [--time]` for headless checks and timings ([perf.md](perf.md)).

## Blame

Who last changed each line: an addition to File history, not a view beside it.
- **Toggle:** one **Blame** toggle at the right end of File history's bar (person icon, the shortcut in its tooltip). On: the selected version's blame replaces its diff. Off: the diff is back. The action `file_history.blame` (Ctrl+Alt+B) toggles it in the File history view (on from a diff, at the caret's line); anywhere else it opens the selected file's history with Blame on. Blame is in no file or diff menu. A newly opened history starts with Blame off. `FileView.set_blame(on, line)`, `toggle_blame()`, `is_blame()`.
- **What is blamed:** the version selected in the list: the file as that commit has it, under the name it had there, or the working copy on the Uncommitted changes row (lines not committed yet read "Uncommitted"). The commit that deleted the file and a deleted working copy have nothing to blame and say so.
- **The blamed file** (`BlameView`, `godot/ui/blame_view/`, a `DiffView` with a leading gutter): the file's text in the diff's font with syntax colours, line numbers, the diff view's text selection, copy, horizontal scroll and minimap. The text shows as soon as it is read; the gutter fills as git reports blocks. A strip above it says what is blamed ("Working copy" / "As of 1a2b3c4 subject"), then "Blaming… 40%" or "68 lines · 10 commits", then the options button.
- **Gutter:** on the first line of each block of lines from one commit, the author's avatar and name and the date (the top row names the commit too, so a long run keeps its name while it scrolls); a thin line separates blocks; an age bar at the gutter's edge tints the newest commits strongest. The tooltip has the subject, author, date and hash.
- **A click on a line** focuses its commit: its details show in the details pane, its lines are highlighted in the text and marked on the minimap strip, and its row in the versions list is marked (not selected: the selection stays the blamed version) and scrolled into view. F7 steps through the focused commit's blocks. Clicking a focused commit's gutter again lets go of it. A version that has no line of the focused commit drops the focus.
- **The blame's menu** acts on the caret's line (a right click puts the caret there), else on the focused commit's first line: **Blame before this commit** (`blame.before`: blames the file as it was before that commit by selecting that version in the list; git names the parent the lines came through, `previous`, and the version is the newest listed commit that parent reaches; it works on uncommitted lines too, going to the last commit; it keeps the caret on the same line number, clears a filter that hides the version, and says "No earlier version in this file's history." when the parent is outside what the view lists), **Show changes** (`blame.show_changes`: Blame off with the focused commit selected), **Open in History**, Copy ▸ hash, **Open version**.
- **Options** (Blame's own sliders button with a `CountBadge`): Ignore whitespace (`-w`, `blame_ignore_whitespace`) and Detect moved lines (`-M`, `blame_detect_moves`), both saved; changing one blames again.
- **Refresh:** the working copy's blame runs again after a status refresh when HEAD or the file's size and time changed; a commit's blame never does. The focused line is kept by number.
- **Core:** `blame` (`BlameParser` of `git blame --incremental`, `BlameTable`, `BlameLoader`, `BlameOptions`, `BlameMinimap`; the text is read first, `cat-file blob <rev>:<path>` or the working file; binary and larger than `LARGE_BLAME_BYTES` are states, not errors), `GitBackend::blame` and `last_change`, `runtime/blame.rs` (`BlameState`; jobs `blame` at normal priority superseding, `load blame commit`, `find blamed version`; `RuntimeEvent::BlameChanged` and `BlameVersionFound`). Closing the file history closes its blame.
- **gdext:** `blame_file_version(oid, ignore_whitespace, detect_moves)` (`oid` empty for the working copy), `close_blame()`, `blame_info()` (`{open, state, oid, path, lines, blamed, commits, loading, error, focus}`), `blame_lines(start, count)` (the diff view's line shape plus `commit`, `first`, `author`, `email`, `time`, `summary`, `age`, `working`, `focus`), `blame_line(line)` (`{commit, author, email, time, summary, working, boundary, path, orig_line, previous, previous_path}`), `focus_blame_commit(oid)`, `blame_details()`, `blame_before(line)`; signals `blame_changed` and `blame_version_found(oid)`. The `blame` slot serves the minimap and `diff_change_row`.
- `gitbello-cli blame <root> <file> [--rev <rev>] [-w] [-M] [--lines a..b] [--time]`.
- Not offered: the history of a line range (`git log -L`), copies from other files (`-C`), an ignore-revs editor (`blame.ignoreRevsFile` is honoured by git itself), blame in the Changes diff.
