# Diff view

Everything about showing a file's changes: viewers and modes, the minimap, middle-click autoscroll, the image viewer, Open in the default app and line endings. It applies to every `DiffPanel` (Changes, History, Shelves, Compare, File history, the resolver). Selection, gaps and staging are in [ARCHITECTURE.md](ARCHITECTURE.md) §3.10; colours in [SYNTAX_HIGHLIGHTING.md](SYNTAX_HIGHLIGHTING.md).

## Viewers and modes

- Each diff has a viewer and the modes it offers. Text: `unified`, `split`. Markdown: also `preview`. Image: `split`, `onion`, `swipe`, `difference`. A file with one side only (added, deleted, untracked; an added or deleted image) offers one mode: unified text, or a single image. A binary that is not an image, an empty diff and a message (loading, too large, error) offer none. A combined diff offers unified only.
- **Core decides** what is offered: `diff::viewer::{Viewer, DiffMode, Offered, offered, conflict_offered}`; `Offered::mode(saved)` is the fallback and `next(current)` the cycle. `diff_info` and `conflict_info` carry `viewer` (`text`, `image`, `none`) and `modes` (in cycle order). Conflicts offer `unified` and `split` for blocks; the binary card has no modes.
- **Saved mode per viewer:** `diff_text_mode` (`unified` default), `diff_image_mode` (`split` default) and `diff_markdown_mode` in `config.toml` (`take_mode` checks them against the viewer's modes); the old `diff_side_by_side = true` reads as `diff_text_mode = "split"`. A file that does not offer the saved mode shows its first mode without changing the setting. `AppCore.diff_mode(viewer)` / `set_diff_mode(viewer, mode)`.
- **One action:** `diff.cycle_mode` ("Next diff mode", Ctrl+Shift+D) moves the shown diff to its next offered mode, wrapping, and saves it for that viewer; every panel showing that viewer follows (`DiffPanel.GROUP`). It works on the focused diff's panel, else the first on screen that offers two modes. A saved shortcut of the old `diff.toggle_side_by_side` moves to it (`RENAMED_ACTIONS`).
- **Picker:** the header's joined icon buttons, one per offered mode, with a tooltip card. Hidden when fewer than two modes are offered; the header keeps the buttons' height so the lines do not move between files. `DiffPanel`: `MODES`, `modes()`, `mode()`, `viewer()`, `picker_visible()`, `can_cycle_mode()`, `cycle_mode()`, `choose_mode(mode)`, `apply_saved_mode(viewer)`.
- Whole file, Show base, the minimap, F7/Shift+F7, Copy and Select all only apply to the text viewer; they hide or disable under the image viewer.
- **Markdown preview** renders the file's blocks with how each changed (`gitbello-cli preview <root> <file>` prints them), its pictures and links resolved against the repository (`diff::markdown`); it has its own scroll strip.

## Minimap

A VS Code-style minimap in place of `DiffView`'s vertical scroll bar.
- **Layout:** a column of about 100 px (theme constant, HiDPI-scaled); the horizontal scroll bar stays. On its right edge, a strip of ~6 px always covers the whole diff.
- **Preview:** rows of the diff as shown (a collapsed gap is its header row, drawn with a thin dashed divider when it hides lines), 2 px per row, one block of about 1 px per character, syntax-coloured, on the row's background: added, removed, hunk header, unchanged; in the resolver ours, theirs and base in the sides' colours; changed words of paired lines in `added_word` / `removed_word`. Lines left out of the commit are dimmed. Side by side: one column, old side in the left half, new side in the right half, row for row. Marker rows draw blank.
- **Scrolling** (VS Code's proportional mode): while the rows fit, the minimap is drawn from the top at 2 px per row; past that it scrolls along so its offset is the diff's scroll ratio times its overflow. A translucent viewport box marks the visible rows: drag it to scroll, click outside it to centre that row, wheel over the column scrolls the diff. Cursors: `CURSOR_DRAG` over the box, `CURSOR_POINTING_HAND` elsewhere.
- **Edge strip:** marks for the whole file, one bucket per pixel: unresolved conflict blocks first, then removed, added and left-out lines, and chosen conflict blocks in green (`OVERVIEW_RESOLVED`); the selection as a faint band; a shade for the visible rows. With hunks collapsed it maps file lines rather than rows shown, so collapsed gaps are empty space (`StripMap`; rows while the file's length is unknown); a click in a gap opens it and scrolls there.
- **Off or narrow:** Settings → Interface → **Show minimap** (`diff_minimap`) and the action `diff.toggle_minimap` (View menu, diff menus). Off, or when the diff is narrower than 600 px, only the strip stays, widened to a scroll bar with a thumb.
- **Data stays in core.** Core renders the preview in tiles of 256 rows straight into RGBA bytes with the colours GDScript passes from the theme (`diff::minimap::{Mark, MiniLine, MiniRow, MinimapSource, DiffMinimap, ConflictMinimap, BlameMinimap, MinimapPalette, MinimapStyle, render_tile, overview, change_row}`), and computes the strip's buckets (one flag byte each: `OVERVIEW_ADDED/REMOVED/CONFLICT/LEFT_OUT/RESOLVED`). Word ranges are computed for tiles only. `RepoSession.diff_minimap_tile(slot, split, first_row, rows, columns, row_px, char_px, palette)`, `diff_overview(slot, split, buckets, whole_file)`, `diff_strip_position(…)`, `diff_strip_target(…)`. GDScript (`godot/ui/diff_view/diff_minimap.gd`) wraps tiles in `ImageTexture`s, keeps a few (LRU), prefetches the tiles just above and below on idle frames, and drops them on a diff, pick, expand, mode, theme or colour change. `VirtualList._scroll_column_width()` leaves room for it.
- **Resolved blocks:** core's `ConflictState` keeps the line ranges block choices wrote this session (shifted by later choices above them, dropped on undo, on an outside change of the file and when the file closes; `merge::record_choice`) and marks those rows `Mark::Resolved`.

## Navigation

- **Next / previous change:** `diff.next_change` (F7) and `diff.previous_change` (Shift+F7). A change block is a run of added, removed or conflict rows in the rows shown (the focused commit's runs in Blame); the jump centres its first row and wraps silently. Core finds it (`RepoSession.diff_change_row(slot, split, from_row, forward)`). Without a previous jump, F7 counts from the middle row. The actions work on the focused diff, else the one on screen.
- **Smooth jumps:** `DiffView.ease_to_offset(target)`, ease-out cubic over 120 ms (`ease_msec` in the theme) for minimap and strip clicks and F7; a mouse press or key finishes it at once, and other scrolling takes over from where it is.
- **History search strip:** the commit list gets a `MarkStrip` (`godot/ui/mark_strip/`, shared with the minimap's strip drawing) beside its scroll bar while a search has matches: hits in the accent colour, the current match stronger; clicking or dragging it scrolls the list (`RepoSession.search_overview(buckets)`).

## Middle-click autoscroll

- **Behaviour** (browser-style, every OS, no setting): a quick middle click (released within ~250 ms without leaving the dead zone) starts sticky autoscroll; holding the button and moving scrolls only while it is held. An anchor icon stays at the click point, the cursor shows the direction, and speed grows with the distance past a dead zone (~8 px, HiDPI-scaled; about `k · d^1.5`, capped). Only the axes that can scroll take part. While running (not headless) it follows the OS cursor past the window edge (`AutoScroll.os_mouse()`).
- **Stops on:** any mouse button (consumed), a wheel turn (which then scrolls normally), Esc (consumed), any other key (passed on), focus loss, or the target hiding or leaving the tree.
- **Where:** every `VirtualList` (lists, the commit list, `DiffView` on both axes), every `ScrollContainer`, `Tree` and `ItemList` through their scroll bars, and multi-line `TextEdit` (by lines; a `TextEdit` with middle-click paste on a system with a primary clipboard keeps its paste). Controls with their own middle click (a worktree chip shows its folder; the `own_middle_click` group) and text fields end the walk. RichTextLabel areas are not covered.
- **Shape:** one `AutoScroll` node (a `CanvasLayer` on top) per window, in `godot/ui/auto_scroll/`. It reads middle presses in `_input`, before the controls, walks up from the hovered control (or `AutoScroll.control_at`, a hit test, where hover is not tracked) and starts on the first scrollable target. `AutoScroll.enable(control)` adds the window's instance; `VirtualList.scroll_axes()` and `scroll_by(delta)` are what it drives. While running it swallows mouse motion (no hover effects); nothing runs while it is idle. Dead zone and speed are theme constants.

## Image viewer

- **Formats** (Godot decodes them, no new crate): PNG, JPG/JPEG, WebP, BMP, TGA, and SVG rendered as an image. Chosen by extension (case-insensitive), confirmed by magic bytes (TGA and SVG have none; SVG is checked for `<svg`). SVG offers the image modes only. A side that fails to decode says "Cannot preview this image".
- **Data:** the bytes load inside the diff job (`diff::image::{ImageFormat, SideImage, ImageSides, read_sides, read_conflict_sides}`), so `DiffChanged` already says when they are ready. `diff_info` and `conflict_info` carry `image` (`{format, old, new}`, each side `{state, size, width, height, id}`; `state` is `image`, `missing`, `too_large`, `too_many_pixels` or `unreadable`); `RepoSession.image_side(slot, side)` adds the side's `bytes`. Dimensions come from the headers before decoding. GDScript decodes on `WorkerThreadPool` and keeps 6 textures by side `id`; an image larger than 2048 px shows a 2048 px preview first and the full image once zoomed past it; one texture uploads a frame.
- **Limits:** over 20 MB a side, the size summary with Load anyway (the diff's `full` flag); over 16384 px on a side (Godot's texture limit), "Too large to preview (W×H)". A conflict's previews are capped at 20 MB without Load anyway.
- **Modes:** *Split* — old | new, each fitted in its half, a caption under each. *Onion skin* — new over old, an opacity slider (starts at 50%). *Swipe* — a vertical divider dragged across reveals old on the left, new on the right. *Difference* — per-pixel absolute difference (`image_difference.gdshader`), unchanged pixels dimmed to a faint copy of the new image. Images of different sizes are aligned at the top-left in onion, swipe and difference, and each side's outline is drawn. Single (one side): the image alone, centred.
- **Zoom and pan:** opens fitted, a small image grown by whole steps (200%, 300%…); the wheel zooms at the cursor through whole levels (100%, 200%… and 1/2, 1/3…, `ZoomLevels`), Shift+wheel and the horizontal wheel pan, a left or middle drag pans, a double-click switches between fit and 100%. The images never leave the view. A zoom bar floats over the top-right corner (Fit, Zoom out, the zoom, Zoom in); actions `image.zoom_in` (Ctrl+=), `image.zoom_out` (Ctrl+-), `image.zoom_actual` (Ctrl+0) and `image.zoom_fit`. In split, both halves share zoom and pan. Nearest filtering past 100%, mipmaps below.
- **Around the image:** a checkerboard behind transparent pixels in theme colours; the header reads `512×512 → 640×480 · 12 KB → 14 KB`. With the view focused, Left/Right move the onion opacity or the swipe divider by 10% (Shift: 1%).
- **Conflicts:** an image's binary conflict card shows ours | theirs previews above Use ours / Use theirs.
- Code: `godot/ui/image_diff/` (`ImageDiffView`), hosted by `DiffPanel` (`set_image_source`, `image_view()`, `zoomable_images()`).

## Open in the default app

- **Open** (`diff.open_file`) in the file lists' and every diff's menu, the resolver's too, and the image viewer's menu over a side: it opens the file with `OS.shell_open`. Changes opens the working copy (a conflict its working file); History, Shelves, Compare and File history open the version shown (the old side for a deleted file).
- Versions come from the target's kind (`<commit>:<path>`, `:<path>` for the index, `HEAD:<path>`, the parent under the original name for the old side), so Open works before the diff loads. They are written to `<cache>/versions/<hash of the bytes>/<file name>` (reused when already there, cleared at startup): `diff::version::{VersionSide, VersionSource, open_version, write_version, clear_versions}`, `Runtime::open_version(key, slot, side)` (job `open file`), `RepoSession.open_version(slot, side)` and `version_ready(path, error)`, handled by `RepoOps` (a toast when it fails).
- There is no "Open in editor" and no editor setting (`editor_command` is read and dropped). Show in file manager and Open terminal stay.

## Line endings

A line's *ending* is LF, CRLF, or none (the last line without a newline), as git compares them: after its clean filter, so a repository that normalizes endings (`autocrlf`, `text`/`eol` attributes) shows no ending changes. A side's endings over some lines are `LF`, `CRLF` or `Mixed`.
- **No newline row:** the line without a final newline is followed by a row of its own, drawn like a hunk header: "No newline at end of file", no line numbers, no checkbox. Unified: after that line; split: on its side only.
- **Line endings row:** when endings changed, one row after the diff's last line (after the lines Show whole file opens, before the end row's expanders): "Line endings: CRLF → LF (3 lines)". Endings changed where a change block's removed lines' endings differ from its added lines' (an insertion: from its hunk's unchanged lines); a line that gained or lost the final newline counts toward the final newline instead. The −/+ lines stay as they are, so staging is unchanged. Split: the row spans both sides.
- **Marker rows** are core layout rows (`LayoutRow::Marker`, kind 5 in GDScript with `marker` `no_newline` or `line_endings`), drawn muted at the line height; they are skipped by selection, Copy, Select all and F7, and kept in Show whole file.
- **Card:** a file whose only changes are endings and/or the final newline shows a card instead of the diff, each change on its own line ("Line endings: CRLF → LF (342 lines)", "Newline added at the end"), with **Show diff** (this file, this session) and, in Changes on the working copy, **Restore line endings**.
- **Restore line endings** (`changes.restore_line_endings`, list and diff menus, the card, the palette): for each selected file with ending changes between the index and the working copy, rewrite the working file so changed lines take the endings the index version had, keeping their text; the final newline goes back when the last line's text is unchanged (`diff::eol::restore_endings`, which checks every shown line against the file first; a file edited meanwhile fails as stale). A write job; the files are backed up first and go on the discard undo stack, so the toast and Edit → Undo take it back. Staged-only changes and untracked files are not touched.
- **Ending-only files in the list:** after each status refresh, a read job (`scan line endings`: `git diff --numstat --no-renames`, then the diffs of modified files with as many lines added as removed, at most 200) finds the files whose changes are endings only; the list shows an `EOL` chip on them, and the filter's **Line endings only** chip narrows to them.
- `diff_info` of a text diff has `endings` (`{from, to, lines}`), `final_newline` (`added`, `removed` or empty) and `eol_only`. Core: `diff::eol::{Endings, Marker, FinalNewline, EndingSummary, summary, restore_endings}`.
- Not offered: a hide-whitespace or ignore-endings toggle, reading or editing `core.autocrlf` / `.gitattributes`, Convert to LF/CRLF, add/remove the final newline.
